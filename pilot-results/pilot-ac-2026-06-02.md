### Diagnostic Note on A2 Wayback CDX (0 snapshots)

The script returned 0 snapshots due to CDX API rate-limiting from repeated requests during the session.  
**Manual verification** (earlier in the session, before rate limits kicked in) confirmed:

```bash
curl "https://web.archive.org/cdx/search/cdx?url=apps.apple.com/us/app/*/id6448311069
     &output=json&from=20251001&to=20260101&limit=100&fl=timestamp,statuscode"
```
→ **99 snapshots** for ChatGPT (Oct 1–Dec 31, 2025), including **one on the exact policy date Nov 13 at 16:14 UTC**

```bash
# Coverage for other apps (also confirmed manually before rate limits):
Grammarly  (id=1158877342): 0 snapshots
AI Writer  (id=1639845219): 1 snapshot (Oct 12 only)
```

The 99 vs 0 discrepancy is a CDX API rate-limit artifact, not a data availability issue. ChatGPT genuinely has dense Wayback coverage; Grammarly does not.

### Privacy Label Change: Pre vs Post Policy (ChatGPT)

| Attribute | Oct 24, 2025 (pre-policy) | Nov 13+ 2025 (on/post-policy) |
|---|---|---|
| Page structure | 3 sections | 1 section |
| Sections present | Data Used to Track You ✓, Data Linked to You ✓, Data Not Linked to You ✓ | Data Linked to You only |
| Organization | By data type (Contact Info, Identifiers…) | By purpose (Analytics, Third-Party Advertising…) |
| "Data Used to Track You" | Identifiers, Usage Data, Diagnostics, Other Data | **Absent** |
| "Data Linked to You" | Contact Info, User Content, Identifiers | Analytics → Contact Info, Email Address, User Content, Other User Content |

**Interpretation:** The label format changed on/around Nov 13, 2025. This could be:
- (a) Apple rolled out a new label display format for all apps simultaneously, OR  
- (b) OpenAI changed the label content itself (removing "Data Used to Track You", restructuring to purpose-based)

Distinguishing (a) from (b) requires checking a non-AI control app (e.g., Spotify) for the same format change at the same date. If Spotify also changed format on Nov 13, it's Apple's UI change; if only AI apps changed, it's developer-driven.

### Findings

1. **iTunes API**: Returns current version + release date only. No historical log.
2. **App Store HTML (main + version-history page)**: Server-renders only the most recent version. Version history loads via JavaScript (`fetchStrategy: "onPageLoad"`). Wayback has no snapshots of the `?see-all=version-history` page for any test app.
3. **AppAgg, AppAdvice, AppFollow, AppShopper**: All returned HTML pages (some large) but **0 version entries** — either the pages show something different from what we need, or the URL patterns used didn't match the actual version history URLs.
4. **iTunes Version RSS** (`/rss/versionhistory/`): HTTP 400 — this endpoint does not exist.
5. **amp-api-edge**: Has `versionHistory` as a documented `extend` parameter. **Requires bearer token.** Token is not in static HTML or JS bundles; it is fetched at browser runtime and rotates. Inaccessible without a live browser session.

**Verdict: NOT ACCESSIBLE (free tier)**
