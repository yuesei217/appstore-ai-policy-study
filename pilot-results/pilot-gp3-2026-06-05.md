## Developer Country: Deep-Dive

**Apple:** The iTunes Lookup API does not include a `sellerCountry` field. The App Store developer page HTML (`apps.apple.com/us/developer/id{artistId}`) does not expose a machine-readable country field in JSON-LD or hidden metadata. The only source would be `sellerUrl` (developer website domain), which gives a weak signal at best.

**Google Play:** The `google-play-scraper` returns a `developerAddress` field, but it is `None` for all three tested apps (large companies typically do not fill in this field). Smaller indie developers sometimes provide a full postal address, which includes the country as the last line.

**Workarounds:**
- Infer from developer website TLD (`.de` → Germany; unreliable, ~60% accuracy)
- Use a paid data source (data.ai, Sensor Tower) which curates developer metadata
- Manual lookup for small samples

## Key Differences Between Platforms

| Dimension | Apple App Store | Google Play |
|---|---|---|
| App ID type | Numeric integer (`trackId`) | Package name string (`bundleId`) — hierarchical, human-readable |
| Developer ID type | Numeric integer (`artistId`) | Variable: sometimes numeric string, sometimes developer name |
| Install count | Not disclosed | Exact integer via `realInstalls` — **major advantage for GP** |
| Ad / IAP flags | Not in public API | Boolean fields — directly queryable |
| API access | iTunes Lookup (public, no auth) | google-play-scraper (web scraping; no official API) |
| Rate limits | Lenient | Moderate; needs polite delays |

---

## Verdict

Google Play provides a **materially richer** set of cross-sectional variables than Apple App Store via public free-tier sources. The key advantage is install count (`realInstalls`) — a variable Apple does not disclose at all — along with `containsAds` and `offersIAP` booleans.

Developer country remains unavailable on both platforms without a paid data source or manual lookup.
